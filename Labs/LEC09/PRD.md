## 2. 목적과 사용자 시나리오

스프라이트 시트에 포함된 소닉의 모든 동작을 자동으로 순환 재생하는 데스크톱 뷰어를 만든다. 사용자는 프로그램을 실행하여 프레임이 잘리는 위치, 재생 순서, 반복 횟수, 동작 전환을 확인할 수 있어야 한다.

기본 시나리오는 다음과 같다.

1. 사용자가 Python 프로그램을 실행한다.
2. 프로그램이 캔버스를 열고 `sonic-sprite.png`를 불러온다.
3. 첫 동작부터 프레임을 순서대로 원본 크기의 4배로 표시한다.
4. 한 동작을 5회 재생한 뒤 마지막 프레임을 1초 동안 유지한다.
5. 다음 동작으로 전환하며, 마지막 동작이 끝나면 첫 동작으로 돌아간다.
6. 사용자가 창을 닫거나 ESC를 누르면 프로그램이 종료된다.

## 4. 기능 요구사항

### FR-01. 이미지 로딩

- 시작 시 제공된 이미지를 한 번 불러오고 재생 중에는 재사용한다.
- 이미지가 없거나 읽을 수 없으면 파일 경로와 원인을 확인할 수 있는 오류를 출력하고 종료한다.
- 시트의 제목, 설명, 제작자 표기와 하단의 다른 캐릭터는 소닉 애니메이션 프레임에 포함하지 않는다.

### FR-02. 동작 및 프레임 등록

- 시트에 포함된 소닉의 모든 동작을 등록한다.
- 기본 순서는 시트의 위쪽 행부터 아래쪽 행으로, 각 동작의 프레임 순서는 왼쪽에서 오른쪽으로 한다.
- 실제 프레임 영역을 검증한 결과는 10종 동작·76프레임이며, 동작별 개수는 8절 표와 같다. 강의 예시의 대조 기준과 일치한다.
- 프레임마다 자르기 사각형과 표시 기준점을 명시한다. 균일한 격자라고 가정하여 서로 다른 크기의 프레임을 일괄 분할하지 않는다.
- 각 사각형은 이미지 범위 안에 있어야 하며, 캐릭터가 잘리거나 인접 프레임이 섞이지 않아야 한다.

프레임 데이터에는 최소한 다음 정보가 있어야 한다.

| 데이터 | 의미 |
| --- | --- |
| 동작 식별자/이름 | 동작을 구분하기 위한 이름 |
| 프레임 목록 | 재생 순서대로 정렬한 프레임 데이터 |
| 자르기 좌표 | 원본 기준 `left`, `top`, `width`, `height` |
| 표시 기준점 | 프레임 크기 변화에도 발 위치 또는 중심을 유지하는 기준 |
| 프레임 간격 | 기본 0.1초; 동작별 변경이 필요하면 명시 |

위에서 아래로 측정한 좌표를 pico2d의 아래쪽 기준 좌표로 변환할 때는 `bottom = image_height - top - height`를 사용한다. 실제 이미지 높이를 이용하며, 좌표 체계를 혼용하지 않는다.

### FR-03. 4배 확대 출력

- 각 프레임의 원본 너비와 높이에 각각 4를 곱하여 표시한다.
- 종횡비를 유지하고, 서로 다른 프레임을 같은 출력 크기로 강제하지 않는다.
- 기본적으로 화면 중앙의 공통 기준점에서 재생한다.
- 공통 기준점과 프레임별 오프셋으로 불필요한 상하 흔들림을 줄이되, 원본 동작의 자세 변화는 유지한다.
- 이미지의 투명 영역을 유지하며 전체 시트를 배경으로 출력하지 않는다.

### FR-04. 동작별 5회 반복

- 한 동작의 첫 프레임부터 마지막 프레임까지 모두 표시한 것을 1회로 계산한다.
- 첫 프레임 표시만으로 반복 횟수를 증가시키지 않는다.
- 마지막 프레임도 다른 프레임과 동일한 재생 시간을 확보한다.
- 5회 재생을 마치면 해당 동작의 정지 상태로 전환한다.

### FR-05. 1초 정지와 다음 동작 전환

- 정지 상태에서는 5번째 반복의 마지막 프레임을 유지한다.
- 정지 시작 시점부터 1초가 지나면 다음 동작의 첫 프레임으로 전환한다.
- 새 동작을 시작할 때 프레임 인덱스와 반복 횟수를 초기화한다.
- 정지 중에도 창 닫기와 ESC 입력을 처리한다. 1초 동안 이벤트 처리를 막는 긴 대기 호출을 사용하지 않는다.

### FR-06. 전체 순환

- 마지막 동작도 5회 반복과 1초 정지를 거친 뒤 첫 동작으로 돌아간다.
- 사용자가 종료하기 전까지 전체 순환을 계속한다.
- 동작을 건너뛰거나, 전환 과정에서 빈 화면을 끼워 넣지 않는다.

### FR-07. 시간 및 상태 관리

- 재생 상태를 `PLAYING`과 `PAUSED`로 구분한다.
- 현재 동작, 프레임 인덱스, 완료한 반복 횟수, 경과 시간을 관리한다.
- 실제 경과 시간을 기준으로 프레임을 진행하며 렌더링 루프의 실행 횟수를 재생 시간으로 사용하지 않는다.
- 시간 측정에는 시스템 시각 변경의 영향을 받지 않는 단조 증가 타이머를 사용한다.
- 누적 시간의 나머지를 유지하여 프레임 전환마다 오차가 쌓이지 않게 한다.

### FR-08. 종료와 자원 정리

- 재생 상태와 정지 상태 모두에서 창 닫기와 ESC로 종료할 수 있다.
- 정상 종료 시 캔버스 자원을 정리한다.
- 초기화 이후 오류가 발생해도 가능한 경우 열린 캔버스를 정리하고 오류 원인을 출력한다.

## 5. 구현 범위와 제외 범위

**기본 요구사항은 제자리 재생으로 확정한다.** 강의 자료의 후속 예시인 위치 이동, 경계 반전, 점프 궤적은 원본 요구사항에 없어 이번 구현 범위에서 제외한다.

이동을 채택하면 구현 전에 동작별 이동 여부, 속도, 좌우 방향, 경계 처리, 점프 높이와 주기를 표로 확정한다. 이동은 프레임 전환과 별개로 경과 시간에 따라 갱신하고, 1초 정지 중에는 프레임과 위치를 함께 유지한다.

이번 기본 범위에는 동작 수동 선택 UI, 재생 속도 조절 UI, 스프라이트 편집, 이미지 내보내기, 사운드, 게임 조작, 외부 시트 가져오기를 포함하지 않는다. 현재 동작명·프레임·반복 횟수 표시는 검증 편의를 위한 선택 기능으로 둔다.

## 6. 개발 단계와 기록

원본의 개발 과정 조건에 따라 **단계별 구현과 검증을 반복하여 최소 20회 커밋을 남긴다.** 커밋 메시지의 설명은 한글로 작성하며, 진행과 검증 결과는 `DEVELOPMENT-REPORT.md`에 기록한다.

| 단계 | 작업 | 단계 완료 기준 |
| --- | --- | --- |
| 1. 요구사항 확정 | 원본 초안 확인, 제안값 결정, 동작 목록과 프레임 수 조사 | 문서의 미확정 항목 해소 |
| 2. 실행 및 출력 | 캔버스, 이미지 로딩, 경로 처리, 단일 프레임 4배 출력, 종료 | 실제 창에서 정상 출력과 종료 확인 |
| 3. 프레임 등록 | 동작별 좌표와 기준점 등록, 각 프레임 확인 | 누락·잘림·인접 프레임 혼입 없음 |
| 4. 재생 로직 | 시간 기반 프레임 전환, 반복 계수, 정지 상태, 전체 순환 | 5회 반복·1초 정지·처음으로 복귀 확인 |
| 5. 통합 검증 | 전체 동작 관찰, 경로 및 오류 처리, 종료 검증 | 아래 인수 기준 충족 및 결과 기록 |

각 단계 안에서 검토 가능한 작은 변경 단위로 커밋한다. 커밋 수를 채우기 위한 빈 커밋이나 의미 없는 수정은 하지 않는다. 개발 시작 기준 커밋을 기록하고, 이후 각 커밋의 변경 내용과 확인 결과를 남겨 개수와 작업 내용을 함께 검토할 수 있게 한다.

## 9. 구현 완료 및 검증 결과

`soninc_animation_viewer.py`에 10개 동작·76프레임과 재생 로직을 구현했다. 4배 출력, 5회 반복, 마지막 프레임 1초 유지, 전체 무한 순환, 창 닫기·ESC 종료를 확인했다. 기준 커밋 이후 문서 확정·구현·검증을 포함한 의미 있는 한글 커밋 27개를 남겼다.

실제 SDL 캔버스를 이용해 모든 프레임의 확대 캡처를 검토했다. 첫 행의 인접 픽셀 혼입을 수정한 후 전체 불투명 픽셀의 누락·중복과 연결 영역의 분할이 없음을 확인했다. 별도의 96초 실시간 재생 검사에서는 전체 두 번의 순환과 20번의 정지를 확인했으며, 정지 시간은 0.993~1.008초였다. 이 장시간 검사는 외부 창 닫기 입력의 영향을 피하도록 SDL 창을 숨긴 상태로 수행했다. 실행 시작부터 종료까지의 총 측정 시간은 97.00초였다.

실행 방법과 단계별 결과, 각 인수 기준의 검증 근거는 `DEVELOPMENT-REPORT.md`를 참조한다.
